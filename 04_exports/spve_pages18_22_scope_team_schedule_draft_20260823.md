# SPVE 立项书 18~22 页草稿：项目范围、团队能力与研发节奏

> 版本：2026-08-23 草稿  
> 用途：先作为讨论底稿，不直接写入在线文档。  
> 当前目标：把 18~22 页从“待补充”变成可讨论的立项落地章节。  
> 写作原则：不空想；用《遗迹 2》等公开数据作为体量参考，再反推 SPVE 的阶段范围、团队能力与节奏。

---

## 0. 参考数据底座：为什么先看《遗迹 2》

《遗迹 2》不是 SPVE 的商业化模板，但它是目前最接近的 **中体量 TPS / PVE / Boss / Build / 刷装** 标杆。它的价值在于：可以帮助我们判断“一个相对完整的射击刷宝 PVE 产品，大概需要什么内容体量和什么团队能力”。

### 0.1 《遗迹 2》公开数据摘录

| 维度 | 公开数据 / 口径 | 对 SPVE 的启发 |
|---|---|---|
| 上线时间 | 2023-07-25 | 近年产品，技术和玩家预期较新 |
| 平台 | PC / PS5 / Xbox Series X\|S | 不是移动端产品；SPVE 若三端互通，技术复杂度会更高 |
| 引擎 | Unreal Engine 5 | 可作为 UE 管线与性能目标参考 |
| 团队规模 | Gunfire Games 2019 年被收购时约 63 名开发者；2022 年团队称已接近 100 人；媒体转述 Reddit AMA 称《遗迹 2》约 90 人参与，其中程序约 8 人 | 《遗迹 2》说明中体量团队可以做出高完成度 TPS PVE，但 SPVE 若叠加移动端、服务型运营、二次元角色更新，实际需要更强外部支持和更大产能 |
| 销量 / 收入 | 首周 100 万+；2023Q3 超 200 万；Embracer 财报披露 Q2 净销售额 7 亿瑞典克朗+ | 中体量 PVE 射击具备商业成立可能 |
| Steam 表现 | SteamDB 历史峰值约 110,856 同时在线 | 证明 PC 端 PVE 刷宝射击可以形成较强启动关注 |
| 世界 / 地图 | 5 个世界：Losomn、Yaesha、N'Erud、The Labyrinth、Root Earth；其中 3 个主世界带随机顺序 / 事件 / Boss / 支线 | 内容体量不是单纯“地图数量”，而是世界主题 + 随机事件 + Boss + 奖励池共同构成复玩 |
| 职业 / Archetype | 首发口径约 10 个 Archetype；初始可选 4 个，其他通过玩法解锁；当前版本含 DLC 已扩展至 14 个 | Build 深度来自职业、技能、Perk、装备的组合，而不是只靠枪械数量 |
| 武器 | 攻略口径约 73~74 把武器，分长枪、手枪、近战；具体首发 / DLC 口径需再按版本归档核对 | 武器数量是中后期目标，不应作为 SPVE Demo 目标 |
| 饰品 / Build 件 | 基础游戏口径包含大量 Amulet / Ring；公开攻略中 Base Game Amulet 约 62，Ring 约 127 | 刷宝深度大量来自低成本高组合度的装备词条件 |
| Boss | 公开攻略口径约 8 个世界 Boss + 20 个左右 mini-boss；不同站点因 alternate boss / aberration 口径不同会有 30~50 档差异 | Boss 与精英怪是 PVE 刷宝的关键内容成本，需拆分“机制 Boss”和“复用精英”两类产能 |
| 游玩时长 | 官方采访口径：主线 20+ 小时，完成全部内容约 60~100 小时；第三方常见口径约 18~20 小时主线、80 小时 completionist | 首发版本若要支撑长线，需要靠随机、掉落、Build 和多周目，而不是纯剧情时长 |
| DLC 计划 | Ultimate 版包含 3 个 DLC 包，承诺上线一年内发布，包含新故事、新生物、新环境 | PVE 刷宝产品需要清晰 DLC / 赛季内容管线，而不是一次性内容消耗 |

### 0.2 不能直接照搬《遗迹 2》的部分

| 差异点 | 《遗迹 2》 | SPVE |
|---|---|---|
| 商业模式 | 买断 + DLC | 倾向 F2P / 服务型 / 外观重付费 |
| 角色商业化 | 弱角色商业化，玩家是自定义角色 | 二次元角色是核心更新与商业化载体 |
| 平台压力 | PC / 主机 | 若三端互通，移动端性能、操作、UI、包体压力更高 |
| 内容更新 | DLC 节奏 | 可能需要版本、活动、角色、外观、赛季长期运营 |
| 美术方向 | 暗黑奇幻 / 科幻废土 | 风格化角色 + 暗黑微恐世界 + 复古朋克异常物件 |

**结论：**  
《遗迹 2》可以作为 **PVE TPS Build 体量上限参考**，但 SPVE 不能按它的完整首发体量直接立项。更合理的是先定义可验证的 Demo / Vertical Slice，再根据验证结果放大团队和范围。

# 第 18 页草稿：项目范围与首版本内容边界

## 页面核心结论

> 首阶段不追求完整首发体量，而是验证“角色 + TPS 射击 + 掉落 Build + 主题关卡 + Boss”的最小闭环；范围必须小于《遗迹 2》首发体量，但要保留足够的刷宝验证价值。

## 建议页面结构

### 18.1 参考上限：《遗迹 2》的内容体量

《遗迹 2》首发已经是相对完整的买断制 PVE 刷宝射击产品：

- 5 个世界 / 大主题区域；
- 约 10 个 Archetype；
- 约 70+ 武器；
- 大量 Amulet / Ring / 装备词条件；
- 约 20+ 小时主线，60~100 小时全收集；
- 大量 Boss、mini-boss、事件、随机支线。

这说明：

> 一个完整 PVE 刷宝射击产品的内容体量很大，SPVE 早期不能直接按完整产品展开，否则会快速失控。

### 18.2 SPVE 建议分层范围

| 层级 | 目标 | 建议内容范围 | 用途 |
|---|---|---|---|
| 原型 Demo | 验证核心体验是否成立 | 1 名角色、1 类核心武器、1 个小型关卡段、1 个精英怪、1 个基础掉落循环 | 验证枪感、镜头、移动端操作、击杀反馈 |
| Vertical Slice | 验证产品闭环是否成立 | 1~2 名角色、1 张主题关卡、1 个 Boss、2~3 类武器、2 条基础 Build、20~30 个装备 / 词条件、1 套外观商业化样张 | 用于立项评审、买量素材、团队能力验证 |
| 首个可测版本 | 验证内容消耗与留存 | 3~4 名角色、2~3 张主题地图、3~5 个 Boss、4~6 类武器、60~100 个装备 / 词条件、基础赛季任务与通行证 | 用于小规模测试、留存和付费意愿验证 |
| 正式首发 | 建立长期运营基础 | 多角色、多主题区域、多 Boss、多流派、多赛季内容 | 不建议现在承诺，应在前两阶段验证后再定 |

### 18.3 当前建议采用的立项口径

建议第 18 页不要写“首版本完整规划”，而写：

> **首阶段范围：Vertical Slice，不是完整首发版本。**

优先验证：

1. 角色是否有厨力和商业化吸引力；
2. TPS 射击是否在移动端与 PC 端都能成立；
3. 掉落和 Build 是否让玩家有继续刷的欲望；
4. 暗黑微恐朋克关卡是否有记忆点；
5. Boss 是否能支撑 PVE 传播和挑战感。

### 18.4 暂不进入首阶段的内容

建议明确排除：

- 大世界；
- 公会 / 大型社交；
- 多人 Raid；
- 完整赛季系统；
- 大量角色池；
- 复杂剧情长线；
- 大规模武器库；
- 大规模关卡随机系统。

这些内容不是不做，而是不作为最早阶段的验证目标。

# 第 19 页草稿：团队能力拆解

## 页面核心结论

> SPVE 不是单一二游项目，也不是单一射击项目，而是“二次元角色商业化 + TPS 手感 + PVE 刷宝 Build + 跨端技术 + 主题关卡”的复合型项目，因此必须拆清核心能力缺口。

## 建议页面结构：能力矩阵

| 核心能力 | 为什么重要 | 对标依据 / 数据支撑 | SPVE 需要验证什么 |
|---|---|---|---|
| UE 跨端能力 | 决定 PC / 移动端 / 未来主机的可行性 | 《遗迹 2》使用 UE5，但只做 PC / 主机；SPVE 若三端互通，性能与输入适配压力更高 | 移动端帧率、包体、触控射击、低端机表现 |
| TPS 射击手感 | 决定产品第一体验下限 | 《遗迹 2》靠 TPS 战斗、Boss、Boss 掉落撑起口碑；Steam 峰值 11 万+说明 PC 用户认可 | 枪感、镜头、命中反馈、换弹、受击、Boss 战读招 |
| PVE 关卡 / Boss | 决定重复刷图是否有内容承载 | 《遗迹 2》5 个世界 + 随机关卡 / 事件 / Boss；不是靠纯数值刷图 | 主题关卡、精英怪、Boss 机制、复刷变化 |
| 刷宝 / Build 系统 | 决定长线留存 | 《遗迹 2》约 10 个 Archetype、70+ 武器、大量戒指 / 护符；Build 深度来自组合 | 2 条基础流派是否足够产生差异；掉落是否有追求感 |
| 二次元角色与人设 | 决定商业化上限 | SPVE 与《遗迹 2》最大差异是角色商业化；角色是版本更新核心 | 角色标签、外观欲望、技能辨识度、角色剧情入口 |
| 风格化渲染 / TA | 决定“角色好看 + 世界危险”能否融合 | 方向是风格化角色 + 暗黑微恐世界；失败会变成拼贴 | 角色材质、怪物质感、场景氛围、移动端表现统一 |
| 商业化 / 运营发行 | 决定 F2P 模型是否成立 | 《逆战：未来》更接近国内三端 PVE 商业样本；《遗迹 2》是买断制，不可直接套商业模型 | 外观付费、通行证、版本节奏、买量素材转化 |

## 建议页面收束

> 能力优先级：射击手感 > 关卡 Boss > Build 掉落 > 角色厨力 > 跨端性能 > 商业化闭环。  
> 如果其中任一核心能力缺失，项目都不宜直接进入大规模量产。

# 第 20 页草稿：项目负责人能力匹配与关键能力缺口

> 注：这页建议不要叫“个人优势 / 劣势”，正式文档里更建议叫“项目负责人能力匹配与关键能力缺口”。这样更像组织评估，而不是个人自评。

## 页面核心结论

> 当前优势在方向定义、竞品判断、角色商业化理解和系统拆解；关键缺口在射击手感、UE 跨端实现、角色美术工业化和高质量 PVE 内容生产。

## 建议页面结构

### 20.1 已具备优势

| 优势 | 对项目的作用 | 可落地到哪些工作 |
|---|---|---|
| 产品方向判断 | 能识别 PVE 刷宝相对 PVP 射击的差异化切口 | 项目定位、竞品框架、用户分层、立项叙事 |
| 角色商业化理解 | 能把二次元角色与外观付费结合，而不是强卖数值 | 角色更新逻辑、外观商业化、PV 表达重点 |
| 叙事与世界观经验 | 能支撑“风格化角色 + 暗黑微恐世界”的概念融合 | 世界观原则、关卡主题、Boss 概念、首曝故事包装 |
| Build / 数值结构敏感度 | 能提前识别刷宝构筑复杂度与收益点 | 属性框架、装备词条、流派验证、Demo 指标 |
| 立项材料组织能力 | 能把概念、竞品、商业、研发范围拆成评审可读内容 | PPT、MD、竞品表、验证计划、风险清单 |

### 20.2 关键能力缺口

| 缺口 | 如果缺失会怎样 | 建议补齐方式 |
|---|---|---|
| 射击手感负责人 | 枪感弱则产品第一体验失败 | 找有成熟 TPS / FPS 项目经验的战斗负责人 |
| UE 跨端技术负责人 | 三端互通、性能、包体、输入适配会失控 | 需要早期介入技术方案与性能预算 |
| 角色美术 / TA 管线 | 角色厨力无法转化为商业化资产 | 需要角色原画、3D、绑定、动作、特效、TA 联合验证 |
| PVE 关卡 / Boss 设计 | 刷图缺乏变化，内容快速消耗 | 需要关卡策划、怪物策划、Boss 机制策划 |
| 刷宝数值负责人 | Build 复杂但不可控，掉落无追求 | 需要装备、词条、掉落、难度曲线专项设计 |
| 运营发行 / 买量支持 | 不知道题材和 PV 是否吸量 | 需要素材测试、用户反馈、预约转化、留存验证 |

## 建议页面收束

> 负责人可以主导“方向定义与验证框架”，但项目成败依赖若干关键专家岗位补齐。建议以核心岗位小组推进 Demo，而不是以完整大团队直接铺开。

# 第 21 页草稿：团队规模随时间预期

## 页面核心结论

> 参考《遗迹 2》约 90 人中体量团队完成 PC / 主机买断制 PVE 射击产品的经验，SPVE 不应一开始组大团队，而应按“验证 → 切片 → 量产准备 → 量产”阶段扩张。

## 参考基准

| 产品 / 团队 | 公开团队口径 | 产品形态 | 对 SPVE 的启发 |
|---|---:|---|---|
| Gunfire Games 2019 | 收购时约 63 名开发者 | Darksiders / Remnant 系列团队 | 中型动作团队起点 |
| Gunfire Games 2022 | 团队接近 100 人 | 多项目经验团队 | 中体量 PVE 射击产品可由 100 人级团队支撑 |
| 《遗迹 2》AMA 转述 | 约 90 人参与，其中程序约 8 人 | PC / 主机买断制 TPS PVE | 设计、美术、关卡、内容产能占比很高；纯程序人数不代表总项目复杂度 |
| Warframe / Digital Extremes | 2024 公开报道约 500 人办公规模；Warframe 官方 80M+ 注册 | 十年以上 F2P 长线服务型刷宝 | 长线运营型刷宝产品最终需要远高于买断制的持续内容与运营产能 |

## SPVE 阶段化团队建议

| 阶段 | 建议规模 | 核心组成 | 阶段目标 |
|---|---:|---|---|
| 概念验证 | 8~15 人 | 制作人 / 战斗策划 / UE 程序 / 原型关卡 / 技术美术 / 角色原画 / 动作 / 特效 | 验证枪感、移动端操作、角色表现、基础掉落反馈 |
| 核心 Demo | 15~30 人 | 增加关卡、怪物、Boss、系统、UI、音频、测试支持 | 做出 1 名角色 + 1 张关卡 + 1 个 Boss + 2 条 Build 的可玩闭环 |
| Vertical Slice | 30~60 人 | 补齐角色 3D、动画、TA、数值、关卡美术、运营商业化样张 | 做出可评审、可测试、可买量验证的完整样板段 |
| 量产准备 | 80~120 人 | 建立内容管线、工具链、跨端性能、版本管理、商业化模块 | 形成可复制的角色、地图、Boss、武器、外观生产流程 |
| 正式量产 | 120~200+ 人 | 多角色、多地图、多系统、多平台、多版本运营团队 | 支撑首发内容与后续版本更新 |

## 关键判断

- 如果目标只是 Demo，不需要一开始对齐《遗迹 2》的 90 人规模。
- 如果目标是三端互通 + 二次元角色 + F2P 长线运营，最终量产规模大概率高于《遗迹 2》。
- 团队扩张必须绑定阶段门槛，而不是按完整梦想版本一次性铺人。

# 第 22 页草稿：研发进度预估

## 页面核心结论

> 研发节奏应先围绕 6 个月内的核心验证，而不是直接承诺完整上线时间；远期计划可以给出 24~30 个月框架，但必须以前期验证结果为前提。

## 建议研发路线图

| 阶段 | 时间 | 目标 | 关键交付物 | 通过标准 |
|---|---:|---|---|---|
| Phase 0：方向收敛 | 0~1 个月 | 明确产品定义与 Demo 范围 | 立项书、竞品数据、用户分层、核心风险清单 | 评审认可 PVE 刷宝方向与验证路径 |
| Phase 1：战斗原型 | 1~3 个月 | 验证 TPS 操作、枪感、怪物、基础掉落反馈 | 1 名灰盒角色、1 类武器、1 个小型战斗场景、1 个精英怪、基础掉落反馈 | 30 秒内能理解玩法；射击与击杀反馈成立 |
| Phase 2：核心 Demo | 3~6 个月 | 验证完整小闭环 | 1 名可展示角色、1 张主题关卡、1 个 Boss、2 条 Build、20~30 个装备 / 词条件 | 玩家愿意重复刷 3~5 局；至少能说出一个想追求的 Build 目标 |
| Phase 3：Vertical Slice | 6~12 个月 | 验证产品样板段 | 2~3 名角色、2 张主题区域、2~3 个 Boss、基础商业化样张、移动端性能版本 | 可用于内部立项评审、买量素材测试、小规模用户测试 |
| Phase 4：量产准备 | 12~18 个月 | 建立生产管线 | 角色管线、武器管线、怪物 / Boss 模板、关卡模板、版本更新框架 | 内容生产效率可预测，核心风险可控 |
| Phase 5：量产与测试 | 18~30 个月 | 面向首发版本推进 | 多角色、多地图、多 Boss、多流派、赛季内容、商业化系统 | 达到测试版本内容量与留存 / 付费验证目标 |

## 建议近端验收指标

第 22 页可以补一组更具体的 Demo 验收指标：

| 指标 | 验证问题 | 建议标准 |
|---|---|---|
| 3 秒识别 | 这个项目看起来是否有记忆点 | 玩家能说出“风格化暗黑朋克 PVE 射击”或类似表达 |
| 30 秒理解 | 玩家是否理解基本玩法 | 看完或上手 30 秒内知道射击、刷怪、掉落、Build 的关系 |
| 10 分钟循环 | 单局是否有继续刷的理由 | 完成一次关卡后愿意再刷一次或换 Build 尝试 |
| 角色吸引 | 角色是否有商业化潜力 | 玩家能记住角色标签，并对外观 / 特效有付费想象 |
| Build 欲望 | 掉落是否形成目标 | 玩家能明确说出想刷什么装备或流派 |
| 移动端可行 | 操作和性能是否能承接 | 基础操作不劝退，核心战斗帧率稳定 |

## 建议页面收束

> 6 个月内的目标不是证明完整产品一定成功，而是证明核心闭环值得继续投入。若枪感、角色吸引、Build 欲望、移动端体验任一关键项不成立，应及时收缩或调整方向。
